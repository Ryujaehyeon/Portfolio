## 설계

- **방법**: 클래스마다 헤더의 멤버 목록과 각 생성자 정의를 대조해 빠진 대상 멤버를 선언 순서대로 초기화 리스트에 넣는다. 생성자 본문의 고정 값 대입(예: `m_iCount = 0;`)은 리스트로 옮기고 본문에서 지운다.
  인자나 계산이 필요한 대입(예: `wcscpy_s`, 함수 호출 결과)은 본문에 두고, 리스트에는 기본값을 둔다.
- **위임 생성자는 쓰지 않는다** — 위임하면 다른 멤버를 리스트에 함께 쓸 수 없어 생성자마다 구조가 갈라진다. 생성자마다 모두 적는 쪽이 단순하다(KISS, intent 결정).
- **기반 클래스 멤버는 기반 클래스 생성자가 맡는다** — 파생 클래스 생성자는 자기 멤버만 적는다(기반 생성자가 모두 초기화하므로).
- **`D3DXMATRIX` 단위 행렬** — 16개 인자 생성자 `D3DXMATRIX(1.f, 0.f, …)` 를 쓴다. 쓰레기 대신 「변환 없음」이 안전한 기본값이다.
- **`OBJINFO` 복사 생성자** — 지금 복사하지 않는 10개(`fX`·`fY`·`fCX`·`fCY`·`matScale`·`matRotz`·`matTrans`·`unitSelect`·`byDrawID`·`byOption`)도 복사한다. 이 생성자는 `CObj(Info, …)` 와
  복제(`Clone` 의 암묵 복사)에서 쓰인다. 지금은 그 값이 쓰레기라 이후 `Initialize` 가 덮어쓰거나 쓰레기인 채 쓰였다 — 원본 값을 갖게 되는 쪽이 의도에 맞다. 스모크로 확인.
- **`SMOKESTATE`** — 기본 생성자를 두면 집합체 초기화(`= { … }`)를 못 쓰므로, 같은 값을 생성자가 주고 정적 변수는 기본 생성한다.
- **검사 스크립트**는 일회용(intent 폴더에 두지 않음) — 헤더를 대략 파싱하므로 결과를 사람이 확인한다.
