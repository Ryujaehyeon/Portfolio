## 요구사항

| ID | 요구사항 | 판정 방법 |
|---|---|---|
| R1 | `CObj::FrameMove` 가 `fStart >= fMax` 에서 0 으로 되돌린다 — 그리는 시점의 프레임 번호가 늘 `[0, fMax)` | 코드 검토 |
| R2 | 각도 계산 4곳(`Player`·`Monster`·`BoneSpear`·`StageDynamic`)의 `acosf` 입력이 `[-1, 1]` 로 잘린다 — 각도가 NaN 이 되지 않는다 | 코드 검토 |
| R3 | `CPlayer::DirectAction`(6개 모션)·`CBoneSpear::DirectAction` 의 8방향 범위가 `[0, 360]` 을 빈틈없이 덮는다: 각 범위의 아래 경계를 포함(`>=`), 오른쪽은 `>= 0 && < 22.5` 또는 `>= 337.5 && <= 360` | 코드 검토 + 경계값 표(아래)로 확인 |
| R4 | 경계가 아닌 각도의 상태 키 선택은 지금과 같다 | 코드 검토(비교 연산자만 바뀜) |
| R5 | 4개 구성 클린 빌드 경고 0·오류 0. Client 스모크 x64 Debug·Win32 Release 각 50회, 나머지 각 5회 PASS(입력 분리 상태) — 경고창·접근 위반 0 | 반복 실행 |

경계값 표(R3): 0°→R, 22.5°→RU, 67.5°→U, 112.5°→LU, 157.5°→L, 202.5°→LD, 247.5°→D, 292.5°→RD, 337.5°→R, 360°→R.

## 설계

- **R1** — `>` 를 `>=` 로. 「한 바퀴 시작」 판정(`fStart <= 0`, ub-fixes)은 리셋 직후 0 이 되는 것이 같으므로 그대로 성립한다. 한 바퀴 길이는 그대로(리셋 시점이 같은 프레임 안에서 경계값일 때만 다름).
- **R2** — `Headers/Function.h` 에 `ClampedAcosf(float)`(입력을 `[-1, 1]` 로 자른 뒤 `acosf`) 한 개를 두고 4곳이 쓴다(DRY). `windows.h` 의 `min`/`max` 매크로를 피해 비교문으로 자른다.
- **R3** — 비교 연산자만 바꾼다(`>` → `>=`, 오른쪽의 `< 360.f` → `<= 360.f`, `> 0` → `>= 0`). 몬스터는 이미 닫힌 구간이고 DEATH·CAST 는 기본값을 먼저 넣으므로 그대로 둔다. `FireWall`·`Blizzard` 는 방향 판정이 없다.
- 텍스처 조회(`CMultiTexture::GetTexture`)에는 범위 검사를 넣지 않는다 — 원인을 고치며, 앞으로 생기는 불일치는 Debug 경고창으로 드러나게 둔다(intent 범위 밖).

## flag된 우려사항

| 무엇이 | 어느 기준에 | 해소 |
|---|---|---|
| Release 의 드문 접근 위반이 이 원인인지 미확정 | 완결성 | 디버거 반복 실행으로 스택을 잡는 중. R5 반복 실행에서 0 이면 해소로 보고, 다른 스택이 잡히면 별도로 다룬다 |
| 경계값에서 고르는 방향이 바뀜(지금은 「안 바꿈」) | 동작 | 의도한 수정 — 이전 키를 유지하던 것이 버그였다 |
