## 한 줄 요약

빈 백엔드 `CRendererD3D11Custom` 과 HLSL 빌드 설정을 준비하고, `docs/render-guide/` 에 8개 장의 가이드와 장별 정답을 쓴다.
정답은 먼저 직접 구현해 B 와 캡처 비교로 검증한 뒤, 코드를 뼈대 상태로 되돌리고 문서로 옮긴다.

## 장 구성

장마다 「Client 를 `-d3d11custom` 으로 실행하면 무엇이 보이는가」를 체크포인트로 둔다. 앞 장의 결과 위에 다음 장을 쌓는다.

| 장 | 제목 | 체크포인트(화면) | 다루는 개념 |
|---|---|---|---|
| 0 | 준비 | 디버그 레이어 메시지를 읽을 수 있다 | 파이프라인 전체 그림, 디버그 레이어, 비교 도구, RenderDoc 으로 프레임 보기 |
| 1 | 장치와 스왑체인 | 창이 지정 색(Client 는 검정, 실습 중에는 눈에 띄는 색 권장)으로 지워진다 | Device·DeviceContext·DXGI 스왑체인(플립 모델)·RenderTargetView·Viewport·Present |
| 2 | 첫 삼각형 | 화면 가운데 삼각형 하나(장 끝에서 지운다) | 정점 버퍼, 입력 레이아웃, VS/PS, HLSL 컴파일, 클립 좌표 |
| 3 | 픽셀 좌표의 사각형 | 스프라이트마다 단색 사각형이 그 위치에 보인다(크기·회전 무시) | 직교 투영, 상수 버퍼, 인덱스 버퍼, 화면 좌표 → 클립 좌표 |
| 4 | 텍스처 | 사각형에 텍스처가 입혀진다(배경이 아직 불투명) | Texture2D·SRV·샘플러, UV |
| 5 | 투명과 색 | 컬러키 배경이 투명해지고, 반투명 UI 가 반투명으로 보인다 | 블렌드 상태(비 premultiplied), 정점 색 곱 |
| 6 | 스프라이트 변환 | **게임 화면이 B 와 같아 보인다** | 중심점·월드 행렬을 정점 4개에 적용, 원본 사각형 → UV, D3DX 행렬(행 벡터) 규칙 |
| 7 | 배칭 | 화면은 그대로, 그리기 호출 수가 크게 준다(RenderDoc 으로 확인) | 동적 정점 버퍼, `Map(WRITE_DISCARD)`, 텍스처가 바뀔 때·버퍼가 찰 때 비우기 |
| 8 | 검증과 다음 단계 | 캡처 비교가 B 대비 허용 범위 안 | 비교 도구 해석, 흔한 차이의 원인(반 픽셀, 샘플러, 블렌드), 더 해 볼 것(인스턴싱, 아틀라스, D3D12) |

### 장 순서를 이렇게 정한 이유

- **눈에 보이는 결과가 매 장 나온다.** 1장의 단색 화면부터 6장의 완성된 게임 화면까지 한 단계씩 쌓인다. 무엇을 추가했을 때 무엇이 바뀌는지 바로 확인할 수 있다.
- **어려운 것을 하나씩 떼어 낸다.** 셰이더(2장), 좌표계(3장), 텍스처(4장), 블렌드(5장), 변환(6장)을 따로 다룬다. 화면이 이상할 때 원인이 그 장의 내용으로 좁혀진다.
- **배칭은 마지막에 한다.** 배칭은 성능 최적화라 화면을 바꾸지 않는다. 먼저 「스프라이트 하나씩 그리기」로 정확한 그림을 만든 다음, 그림이 그대로인지 확인하며 최적화한다.

## 설계

### 정답을 먼저 만들고 뼈대로 되돌리는 이유

가이드의 힌트와 체크포인트가 실제 코드와 어긋나면 학습자가 가장 크게 헤맨다. 그래서 순서를 이렇게 한다.

1. 장 순서대로 실제로 구현한다. 장이 끝날 때마다 그 시점의 코드를 정답 문서로 옮긴다. 이것이 「그 장에서 바뀌는 부분」이 된다.
2. 8장까지 마친 코드를 B 와 캡처 비교로 검증하고 `solutions/complete/` 에 보관한다.
3. 코드를 뼈대 상태로 되돌려 커밋한다. 학습자는 뼈대에서 시작한다.

### 셰이더 빌드

- vcxproj 의 `FxCompile` 항목으로 `.hlsl` 을 빌드 때 컴파일한다. 출력은 바이트코드 배열을 담은 헤더(`/Fh`)다.
  실행 파일에 셰이더가 들어가므로 실행할 때 셰이더 파일 경로를 신경 쓰지 않아도 된다(resource-path 문제와 무관).
- 셰이더 모델은 4_0(기능 수준 10_0 과 맞춤).

### 학습자가 막혔을 때의 길

가이드 README 에 단계별 대처를 적는다.

1. 디버그 레이어 메시지를 본다(0장에서 보는 법을 익힌다).
2. 체크포인트 그림과 비교한다.
3. RenderDoc 으로 프레임을 잡아 파이프라인 상태(정점·셰이더·블렌드)를 본다.
4. B 의 같은 부분(`CRendererD3D11Tk`)과 DirectXTK 소스를 본다.
5. 그 장의 정답을 연다.
