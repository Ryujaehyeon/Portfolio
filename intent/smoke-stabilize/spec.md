## 요구사항

| ID | 요구사항 | 판정 방법 |
|---|---|---|
| R1 | `CObj::CObj(const OBJINFO&, const TCHAR*, const OBJ_TYPE)` 가 `m_dwKey(0)` 으로 초기화한다 — 세 생성자 모두 `m_dwKey` 를 초기화 | 코드 검토 |
| R2 | 스모크 시전이 실제 우클릭 시전과 같은 두 자리(목표 도달 / 도달하지 못함)에서 시도된다. 도달하지 못한 분기에서는 우클릭과 같이 목표를 현재 위치로 두고(`m_vTagetInfo = m_Info.vPos`) `SkillActive(BONESPEAR)` | 코드 검토, `IsSmokeMode()` 안 |
| R3 | x64 Release Client 스모크 **30회 연속** PASS(수정 전 30회 중 3회 실패), 나머지 3개 구성 각 5회 PASS. 툴 스모크 4개 구성 PASS | 반복 실행 |
| R4 | 4개 구성 클린 빌드 오류 0·경고 0(`/WX`), 일반 실행 8초 살아 있음 | CLAUDE.md |
| R5 | FIX-GUIDE 「다음 순서」에서 끝난 `warning-cleanup` 을 지운다 | 문서 검토 |

## 설계

- **R1** — 다른 두 생성자와 같은 자리(`m_Crash(false)` 다음)에 `, m_dwKey(0)`. 그 밖의 멤버는 범위 밖(intent).
- **R2** — `CPlayer::CheckKey` 의 「도달하지 못했을 때」 분기에서 우클릭 다음에 `else if (bSmokeCast)` 를 둔다: 우클릭과 같은 순서로 목표를 현재 위치로 두고 시전.
  다음 프레임부터 도달 분기의 스모크 시전이 이어지므로 시전 애니메이션이 끊기지 않는다. 방향(`vDir`)·각도는 스모크에 필요 없어 넣지 않는다(KISS).
- 근거: 스모크는 「사람이 우클릭을 누르고 있는 상황」을 흉내 내야 하는데, 지금은 그중 절반(도달 분기)만 흉내 낸다.

## flag된 우려사항

| 무엇이 | 어느 기준에 | 해소 |
|---|---|---|
| R1 이 `-smoke` 없는 게임 동작을 바꿈 | 동작 불변 | 의도한 수정(미초기화 → 0). 시작 직후 선택이 무작위로 풀리던 버그가 사라질 뿐, 키를 누르기 전 상태는 「아무 키도 안 눌림」이 맞다 |
| 30회도 확률적 판정 | 검증 강도 | 수정 전 실패율 약 10%(30회 중 3회) → 30회 연속 PASS 면 우연일 확률 약 4%. 원인 두 가지를 로그로 직접 확인했으므로 반복 실행은 확인용 |
