# Coding Standard Check

코드를 표준과 대조해 **보고서만** 쓴다. 소스는 수정하지 않는다 — 수정은 보고서를 보고 개발자가 한다.

## 입력

1. 표준 원문 `.harness/standards/cpp11-coding-standard.md` 를 읽는다. **기준은 이 파일뿐이다.** 기억이나 다른
   표준으로 항목을 만들지 않는다. 항목 번호는 `<장>-<번호>` 로 쓴다: 머리말 `P-1~4`, I장 `I-1~62`, II장 `II-1~6`,
   III장 `III-1~12`, IV장 `IV-1~2` (예: `I-56` = I장 56번).
2. 대상 저장소 `CLAUDE.md` 의 「C++ 코딩 표준」 절을 읽는다(템플릿: `.harness/templates/product-CLAUDE.md`).
   여기서 적용 범위·언어 표준·검사 제외 경로를 가져온다. 표준도 「프로젝트 규칙과 충돌하면 프로젝트 규칙 우선」이라
   적고 있으므로 이 절이 표준보다 앞선다. 적용 범위 표는 대상에 맞는 행을 쓴다 — 이번에 새로 만든 파일은 「새 코드」,
   그 밖은 「고치는 코드」. 「기존 관례 유지」에 든 항목은 보고하지 않고 제외 목록에 적는다. 절이 없으면 아래 「항목 분류」 전체로 검사하고 보고서에
   「적용 범위 미정」이라 적는다.
3. 대상을 정한다 (`$ARGUMENTS`):

   | 인자 | 대상 |
   |---|---|
   | 없음 / `diff` | 변경분 — git 은 `git diff HEAD` 와 untracked 파일, SVN 작업본은 `svn diff` 와 미등록(`?`) 파일 |
   | 경로(파일·폴더, 여러 개 가능) | 그 안의 파일 전체 |
   | 브랜치 이름 | `git diff <기본 브랜치>...<브랜치>` 의 변경 줄 |
   | PR 번호 | `gh pr diff <번호>` 의 변경 줄 |

   - 검사 파일은 C++ 확장자만: `.cpp .cc .cxx .h .hpp .hxx .inl`. IV장은 대상에 `.vcxproj`·`.props` 가 있을 때만 본다.
   - CLAUDE.md 의 검사 제외 경로(서드파티·생성 파일)는 뺀다.
   - 남는 파일이 없으면 멈추고 무엇이 비었는지 말한다.
4. 옵션
   - `--all`: CLAUDE.md 적용 범위와 무관하게 「항목 분류」 전체로 검사한다(참고용). 범위 밖 항목에는 「범위 밖」 표시를 붙인다.
   - `--rules I-56,III-4`: 지정한 항목만 검사한다.
   - `--max N`: 상세를 N 건까지만 쓴다(요약 집계는 전체). 기본은 제한 없음.

## 항목 분류

표준 원문을 검사 관점으로 나눈 것이다. CLAUDE.md 적용 범위는 이 분류 이름이나 항목 번호로 적는다.

| 분류 | 항목 | 비고 |
|---|---|---|
| 품질 | I-18~23, I-26~28, I-33, I-53, I-54, I-56, I-57, I-58, III-1, III-3, III-4, III-6, III-8, III-10 | |
| 명명 | I-1~15, I-29, I-35~37, I-47 | 기존 코드와 섞이면 한 파일에 두 스타일이 생긴다 — 적용 범위를 먼저 확인 |
| 설계·구조 | I-16, I-17, I-30~32, I-34, I-42, I-43, I-45, I-46, I-48~52, I-55, I-59~61, III-2, III-5, III-7 | 고치면 호출부가 연쇄로 바뀔 수 있다 |
| 기반 코드 전제 | I-24, I-25, I-38~41, I-44 | `FALLTHROUGH`·`Assert`·`New`/`Delete`·`MemSet` 등이 **저장소에 정의돼 있을 때만** 검사. 없으면 「전제 없음」으로 제외 |
| 포맷팅 | II-1~6 | 저장소에 포매터 설정이 있으면 그 설정이 우선 |
| 프로젝트 설정 | IV-1, IV-2 | Visual C++ 프로젝트 파일이 대상일 때만 |
| 검사 안 함 | P-1~4, I-62, III-9, III-11, III-12 | 머리말은 원칙, III-9 는 허용 규칙, I-62·III-11·III-12 는 표준이 「미정」으로 둔 항목 |

언어 표준: CLAUDE.md 에 적힌 언어 표준(없으면 C++11 로 본다)에서 쓸 수 없는 기능을 요구하는 항목은 보고하지 않고
「컴파일러 미지원」으로 제외 목록에 적는다. 표준은 C++11 기준이라 C++14 이상의 규칙은 들어 있지 않다.

## 검사 방법

1. 대상 파일을 **실제로 읽는다.** 줄 번호는 파일의 현재 내용 기준(1부터). 변경분이 대상이면 변경된 줄과 그 함수만 본다.
2. 항목마다 근거가 되는 코드 줄을 찾는다. 코드에서 보이지 않는 위반은 보고하지 않는다. 판단이 애매하면 보고하되
   「판단 필요」로 표시한다.
3. **I-56(경고)** 은 추측하지 않고 빌드 출력으로 판정한다. CLAUDE.md 「빌드 / 테스트 / 린트」의 빌드 명령을 실행하고,
   경고 줄 중 대상 파일을 가리키는 것만 모은다(컴파일러마다 형식이 다르다 — MSVC `file(line): warning C4715`,
   GCC/Clang `file:line:col: warning:`). 빌드 명령이 없거나 이 환경에서 빌드할 수 없으면 I-56 은 「미검사」로 적는다.
4. 같은 항목이 한 파일에서 반복되면 줄마다 하나씩 쓴다. 같은 패턴이 10건을 넘으면 대표 3건만 상세로 쓰고 나머지는
   「동일 패턴」 표에 `파일:줄` 만 나열한다.
5. **수정 후**는 그 줄만 바꾼 최소 변경으로 쓴다. 다른 항목의 수정이나 주변 정리를 섞지 않고, 적용 범위 밖의 기존 관례
   (예: 기존 멤버 이름)는 그대로 둔다. 여러 줄을 함께 바꿔야 하면 바뀌는 범위 전체를 보인다. 동작이 바뀔 수 있거나
   다른 파일도 고쳐야 하면 「주의」에 적는다.
6. 코드 인용은 원문 그대로(탭·공백 유지), 언어 태그 `cpp`.

## 출력

보고서를 파일로 쓴다. 경로: `docs/coding-standard/<YYYY-MM-DD>-<대상>.md` (폴더가 없으면 만든다)
- `<대상>`: 파일 하나면 확장자를 뺀 파일명, 폴더면 폴더명, 변경분이면 `diff` 또는 `diff-<브랜치명>`, PR 이면 `pr-<번호>`.
  소문자·하이픈.
- 같은 이름이 있으면 `-2`, `-3` 을 붙인다. 덮어쓰지 않는다.
- UTF-8(BOM 없음) 마크다운.

양식:

````markdown
# 코딩 표준 검사: <대상>

- 일시: <YYYY-MM-DD HH:MM>
- 대상: <경로 또는 diff 범위>, 파일 N개
- 기준: `.harness/standards/cpp11-coding-standard.md` · 범위: CLAUDE.md | 적용 범위 미정(전체) | 전체(--all) | --rules <항목>
- 결과: 위반 N건 (항목 M종) · 미검사: <없음 | I-56 (빌드 불가) 등>

## 요약

| # | 파일:줄 | 위반 항목 | 비고 |
|---|---|---|---|
| 1 | `src/Foo.cpp:6` | III-4 포인터에 `NULL` 대신 `nullptr` 를 사용한다 | |

## 상세

### 1. `src/Foo.cpp:6` — III-4 포인터에 `NULL` 대신 `nullptr` 를 사용한다

**수정 전**
```cpp
	: mBar(NULL)
```

**수정 후**
```cpp
	: mBar(nullptr)
```

> 주의: <필요할 때만 — 동작이 바뀔 수 있는 점, 함께 고쳐야 할 곳>

## 동일 패턴 (대표 3건 외)

| 위반 항목 | 위치 |
|---|---|
| III-4 | `src/Foo.cpp:12`, `src/Foo.cpp:40` |

## 미검사·제외

- <검사하지 못한 항목과 이유, 범위 밖·전제 없음·컴파일러 미지원으로 제외한 항목과 건수, 제외한 경로>
````

규칙:
- 「위반 항목」은 `<번호> <원문 제목>` 이다. 원문 제목이 길면 줄이되 뜻을 바꾸지 않는다.
- 위반이 0건이면 요약 표 대신 「위반 없음」과 검사한 항목 목록을 쓴다.
- 보고서를 쓴 뒤 사용자에게는 **경로와 건수 요약만** 말한다. 보고서 내용을 대화에 다시 붙이지 않는다.
- 보고서를 커밋하지 않는다. 커밋 여부는 사용자가 정한다.
