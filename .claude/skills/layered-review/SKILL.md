# Layered Review

변경을 레이어별로 점검한다. 리뷰 기준은 이 파일에 다시 쓰지 않고 원칙 문서를 따른다.

## 입력

1. `.harness/sdlc/review-layers.md` 를 읽는다. 레이어 정의와 판별 질문의 기준이다.
2. 대상 저장소 루트에 `REVIEW.md` 가 있으면 읽는다. 실패의 정의·Nit 상한·제외 경로·요약 형식은 이 규정을 따른다.
   Claude Code 의 로컬 `/code-review` 는 `REVIEW.md` 를 읽지 않으므로 이 스킬이 대신 적용한다.
3. `CLAUDE.md` 를 읽는다. 관례를 어기는 변경, `CLAUDE.md` 의 내용을 낡게 만드는 변경도 지적 대상이다.
4. 대상 diff 를 구한다. 인자가 없으면 `git diff HEAD` 와 untracked 파일, 브랜치면 `git diff <base>...<브랜치>`, PR 이면 `gh pr diff <번호>`.
   SVN 작업본이면 `svn diff` 와 `svn status` 의 미등록(`?`) 파일.

## 절차

레이어마다 판별 질문에 답하고, 근거를 단다. 로컬에서 확인할 수 없는 레이어는 추측하지 않고 "확인 불가"로 남긴다.

| 레이어 | 이 스킬이 하는 일 |
|---|---|
| 1 사전 검증 | 변경을 뒷받침하는 실행 결과(테스트·빌드 출력)가 있는지 본다. 없으면 실행할 명령을 제시한다. 반복될 지적은 린트·skill·`CLAUDE.md` 로 옮길 후보로 표시한다. |
| 2 AI 리뷰 | diff 를 저장소 전체와 변경 의도에 대조해 버그를 찾는다. 문제를 푸는가 / 시스템에 맞는가 / 다른 것을 깨는가. |
| 3 보안 | 비밀정보·입력 검증·권한·의존성을 본다. 깊게 보려면 Claude Code 의 `/security-review` 를 권한다(없는 도구에서는 이 레이어를 직접 점검한다). |
| 4 자동 검사 | 저장소의 린트·테스트·빌드 명령을 찾아 실행하고 실제 결과를 적는다. 명령이 없으면 없다고 적는다. |
| 5 사람 승인 | 변경의 위험 등급(Low/Medium/High)과 필요한 사람 승인 수를 판정한다. 승인을 대신하지 않는다. |
| 6·7 머지·롤백 | 플래그·되돌리기 방법이 있는지만 확인한다. 없으면 "How to revert" 를 적어 달라고 한다. |

## 지적 규칙

- 심각도는 `Important` / `Nit` / `Pre-existing` 중 하나. 이번 변경이 만들지 않은 문제는 `Pre-existing`.
- 동작에 관한 지적은 `file:line` 근거를 단다. 이름만 보고 추측한 지적은 버린다.
- 스타일·정리만인 지적은 Nit 이하. Nit 상한은 `REVIEW.md` 를 따르고, 없으면 5개.
- 한 줄이 아니라 버그의 종류를 지적하고, 같은 종류의 다른 위치를 함께 적는다.
- 보고 전에 각 지적을 코드로 다시 확인한다. 확인되지 않으면 버린다.
- 다시 리뷰할 때는 이미 올린 지적을 반복하지 않고 새 diff 만 본다. 3라운드를 넘으면 접근 방식 재검토를 권한다.
- 코드를 고치지 않는다. 수정은 사용자가 요청할 때만 한다.

## 보고 형식

```
Important N, Nit N, Pre-existing N   ← 없으면 "고칠 것 없음"
위험 등급: Low|Medium|High — 필요한 사람 승인 N명 (근거)

[레이어별 결과]
1 사전 검증: 통과|미흡|확인 불가 — 근거
...

[지적]
- Important `file:line` — 무엇이 깨지는가, 근거
```

실행하지 않은 검사를 통과했다고 쓰지 않는다.
