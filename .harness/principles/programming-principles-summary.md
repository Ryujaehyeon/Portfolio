# 프로그래밍 원칙

> **요약본**이다. 이 저장소에서 코드 판단의 기준으로 쓴다.

| 원칙 | 핵심 |
|---|---|
| KISS | 동작하는 가장 단순한 것을 고른다. |
| DRY | 같은 지식을 여러 곳에 두지 않는다. |
| YAGNI | 지금 필요하지 않은 것을 미리 만들지 않는다. |
| PIE | 코드가 의도를 표현하게 쓴다. |
| SLAP | 한 함수 안의 추상화 수준을 맞춘다. |

---

## KISS — Keep It Simple, Stupid

단순성을 최우선으로 둔다. 코드는 그냥 두면 무질서해지고 복잡해져 읽기도 고치기도 어려워진다.

**실천**: 쓰기 전에 "동작하기 위해 가장 단순한 것은 무엇인가"를 묻는다.

## DRY — Don't Repeat Yourself

같은 **지식**을 여러 곳에 두지 않는다. 중복이 있으면 하나를 고칠 때 나머지를 빠짐없이 찾아 고쳐야 하고, 놓치면 조용히 어긋난다.

**실천**: 처리는 함수·모듈로 모으고, 값은 이름 있는 상수로 둔다. 규칙이 여러 곳에서 필요하면 **한 곳에 두고 공유**한다.

**주의**: 우연히 같아 보이는 코드는 중복이 아니다. 같은 이유로 함께 바뀌는 것만 묶는다.

## YAGNI — You Aren't Going to Need It

미리 대비해 쓴 코드는 대개 쓰이지 않고, 쓸데없는 복잡성만 남긴다. 예상이 빗나가면 시간을 버린 데다 방해까지 된다.

**실천**: 범용성보다 단순성을 고른다. "지금" 필요한 것만 만든다. 단순한 코드가 오히려 범용성이 높다.

## PIE — Program Intently and Expressively

코드는 사람이 읽는 것이고, 소프트웨어의 동작을 정확·완전히 아는 유일한 단서다.

**실천**: "쓰기 쉬움"보다 "읽기 쉬움"을 택한다. 코드는 쓰는 횟수보다 읽히는 횟수가 훨씬 많다.

## SLAP — Single Level of Abstraction Principle

한 함수 안에서 높은 수준과 낮은 수준의 처리를 섞지 않는다.

**위반 신호**: 한 함수가 업무 규칙을 다루다가 곧바로 DB 접속·문자열 파싱 같은 세부로 내려간다.

**실천**: 수준에 맞게 함수를 나눈다. 그래야 요약해 읽는 것과 자세히 읽는 것이 동시에 가능해진다.
